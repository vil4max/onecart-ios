# OneCart: нативная iOS-архитектура

Нативный target `App` реализован на SwiftUI. Supabase отвечает за аккаунты, семейные права и общие данные; Core Data обеспечивает мгновенную локальную работу и офлайн-режим.

## Компоненты

- `ManagedObjects.swift` — программная Core Data-модель и отображаемые свойства.
- `PersistenceController.swift` — два совместимых локальных SQLite store для сохранения существующих установок. Оба работают как локальный кэш.
- `FamilySpaceRepository.swift` — локальные CRUD-операции, проверки ввода и tombstone-удаления.
- `SupabaseServices.swift` — Supabase Auth, RPC, DTO и Realtime-подписка.
- `FamilySyncService.swift` — создание snapshot, timestamp merge и применение серверного состояния к Core Data.
- `AppModel.swift` — аккаунт, выбранная семья, синхронизация, приглашения и UI-состояние.
- `RootView.swift` — вход, регистрация, первое семейное пространство и основные вкладки.
- `SettingsView.swift` — аккаунт, участники, приглашения, выход и семейные действия.
- `ShoppingViews.swift` — существующий сценарий списков, магазинов, товаров и истории.

## Авторизация

OneCart использует Supabase Auth с email и паролем.

1. При регистрации отправляются имя, нормализованный email и пароль.
2. Имя записывается в user metadata и серверный `profiles` через auth-trigger.
3. Supabase Swift SDK хранит сессию в Keychain.
4. Если в проекте включено подтверждение email, пользователь подтверждает письмо и затем входит обычной формой.
5. После выхода кэш другого аккаунта не показывается. Каждая локальная семья помечена `cachedForUserID`.

Publishable key находится в клиенте намеренно и защищается RLS. Service-role key и любые административные секреты в iOS target отсутствуют.

## Семья и приглашения

- Создатель пространства получает роль `owner`.
- Владелец создаёт одноразовую ссылку и отправляет её через системное iOS-меню «Поделиться».
- HTTPS-ссылка открывает минимальную Supabase Edge Function, а кнопка на ней возвращает пользователя в приложение через `onecart://invite/<token>`.
- Токен действует 14 дней и погашается первым новым участником. До входа он сохраняется локально, а после авторизации приложение показывает название семьи и число участников перед подтверждением.
- После принятия создаётся membership с ролью `member`.
- Владелец может менять название, приглашать и удалять участников.
- Участник может совместно редактировать покупки и покинуть семью.
- Владелец не может случайно удалить самого себя через member API.

Доступ проверяется на сервере через Postgres Row Level Security и повторно внутри привилегированных RPC. Метаданные клиента не используются для принятия security-решений.

## Серверная модель

Миграции находятся в `supabase/migrations/` и создают:

- `profiles`
- `families`
- `family_members`
- `family_invitations`
- `private.family_invite_links`
- `stores`
- `shopping_lists`
- `products`
- `purchase_history`
- `history_items`

Все public-таблицы используют UUID primary keys, `timestamptz`, явные constraints, индексы для foreign keys/RLS и включённый RLS. Клиент работает через ограниченную роль `authenticated`.

Основные RPC:

- `ensure_family`
- `create_family_invitation`
- `accept_family_invitation`
- `create_family_invite_link`
- `get_family_invite_preview`
- `accept_family_invite_link`
- `leave_family`
- `remove_family_member`
- `get_my_families`
- `get_family_members`
- `get_pending_invitations`
- `get_family_snapshot`
- `sync_family_snapshot`

Snapshot ограничен 5000 строками на одну синхронизацию, чтобы не допускать неограниченный payload.

## Offline-first синхронизация

Любое изменение сначала сохраняется в Core Data и сразу становится видимым в UI.

1. Клиент собирает полный timestamped snapshot выбранных локальных семей.
2. `sync_family_snapshot` выполняет upsert только когда входящий `updated_at` новее серверного.
3. Сервер возвращает канонический snapshot.
4. Клиент применяет строку, только если серверная версия не старее локальной.
5. Realtime-событие запускает debounced повторную синхронизацию.
6. При отсутствии сети UI показывает офлайн-состояние; локальные изменения не блокируются.

Удаления представлены `deleted_at`, а не физическим удалением. Такой tombstone доходит до всех устройств и не позволяет старому офлайн-клиенту «воскресить» удалённый товар. Физическая очистка локальной семьи выполняется только после подтверждённого выхода или потери membership.

Существующие данные старой установки не пропадают: первое успешное подключение аккаунта помечает непривязанные локальные пространства как принадлежащие этому пользователю и загружает их на сервер.

## Сборка

Используется одна схема `App`. Debug и Release подписываются пустым `AppLocal.entitlements`; возможностей iCloud и Push Notifications нет.

```bash
cd ios/App
xcodebuild \
  -project App.xcodeproj \
  -scheme App \
  -configuration Debug \
  -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO \
  build
```

Для запуска на iPhone выберите Development Team и устройство в Xcode. Supabase не требует платной Apple Developer Program; ограничения бесплатной подписи Apple относятся только к установке сборки на устройство.

## Проверка на двух аккаунтах

1. На первом устройстве зарегистрируйте владельца и создайте семью.
2. Добавьте несколько продуктов, в том числе один раз без сети.
3. В разделе «Семья» нажмите «Пригласить» и отправьте ссылку второму пользователю через системное меню.
4. На втором устройстве откройте ссылку, нажмите «Открыть в OneCart» и зарегистрируйтесь либо войдите.
5. Проверьте превью семьи, примите приглашение и откройте общий список.
6. Измените товар на каждом устройстве и убедитесь, что Realtime обновляет второе.
7. Удалите товар офлайн, верните сеть и убедитесь, что он исчез на обоих устройствах.
8. Выйдите и войдите снова: Supabase-сессия и scoped Core Data-кэш не должны показывать данные другого аккаунта.

## Ограничения текущей версии

- Восстановление пароля не показывается, пока для проекта не настроен production redirect URL/deep link.
- При включённом подтверждении email доставка письма зависит от Auth email provider/SMTP проекта Supabase.
- Клиент требует пароль минимум из 8 символов. Проверка по базе утёкших паролей относится к Supabase Pro и недоступна на бесплатном плане.
- Конфликты разрешаются по `updated_at` на уровне строки; совместное редактирование одного поля не является CRDT.
