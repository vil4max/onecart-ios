# ADR 0001: Supabase как основной backend OneCart

- Статус: принято
- Дата: 2026-07-16

## Контекст

OneCart должен поддерживать отдельные аккаунты, приглашение семьи, совместные списки и работу без сети. CloudKit Sharing требует Apple capabilities и платной программы разработчика, не даёт приложению собственной понятной email-регистрации и затрудняет управление семьёй внутри интерфейса OneCart.

## Решение

Использовать Supabase как основной backend:

- Supabase Auth для email/password и Keychain-сессии;
- Postgres как каноническое хранилище;
- RLS и серверные RPC для family membership и приглашений;
- Realtime для уведомления клиентов об изменениях;
- Core Data как offline-first локальный кэш;
- timestamped snapshots и tombstones для двусторонней синхронизации.

Отдельный custom API-сервер на этом этапе не создаётся. Бизнес-операции, требующие повышенных прав, инкапсулированы в минимальных RPC, а обычные таблицы защищены RLS.

## Рассмотренные альтернативы

### CloudKit + CKShare

Отклонено из-за зависимости от Apple Developer capabilities, отсутствия собственной email-модели аккаунта и неудобного для продукта системного sharing flow.

### Собственный сервер и база данных

Отложено. Он дал бы максимальный контроль, но потребовал бы отдельного auth, API, деплоя, мониторинга и security lifecycle без пользы для текущего масштаба.

### Только локальное хранилище

Отклонено: не решает семейный доступ и синхронизацию между устройствами.

## Последствия

Положительные:

- одна понятная регистрация внутри OneCart;
- семейные роли и приглашения не зависят от Apple ID;
- приложение продолжает работать офлайн;
- серверная авторизация проверяется независимо от клиента;
- backend можно развивать без выпуска новой версии iOS для каждой схемной операции.

Компромиссы:

- появляется зависимость от Supabase availability и правил Auth email delivery;
- last-write-wins по строке не объединяет параллельное редактирование одного объекта;
- snapshot-подход имеет лимит размера и позже может потребовать incremental sync;
- production потребуется наблюдение за квотами, логами Auth/Postgres/Realtime и SMTP.
